## 速度证据

与第一提交进行交替顺序的重复配对，剔除两对预热。普通正式心情流程共 30 对、每对各 600 场，中位耗时 **217.34 → 204.63 微秒／场**。配对差值均值的 95% bootstrap 区间为 [-14.89, -11.96] 微秒。另逐步核对 **12000 次**无观测更新：上下限、中间值和等待目标一致；正式流程的最终状态和保存次数也一致。

真实 ALAS 心情 OCR 的匿名截图流程共 12 对，每次调用原有三类扫描，中位耗时 **1175.85 → 1178.01 毫秒**；配对差值均值的 95% bootstrap 区间为 [-3.84, 58.63] 毫秒。离线设备替身的操作顺序和次数一致：点击调用 7、截图 6、分类扫描 3、OCR 调用 9、配置保存 1；新增等待为零。这里的点击和部分 OCR 使用替身，真实执行的是心情 OCR，不能当作实机操作耗时。

去掉 OCR 的替身扫描 CPU 中位耗时 **114.00 → 206.45 微秒**，如实包含学习本身的计算开销。没有增加游戏操作、截图、OCR、磁盘轮询或等待。普通计算的优化抵消了所测常规流程开销，带真实心情 OCR 的流程未检出稳定减速；**这些离线数据不能证明所有设备、后端或实机耗时完全相同**，实机速度由用户验收。

## 实机测试

1. 停止出击，重启 ALAS 加载新 Python 代码。不要在仍运行的旧进程中判断新逻辑是否生效。
2. 确认港区／后宅楼层及誓约条件，暂停出击后填写参与舰队的实测最低心情。即使与旧值相同也清空重填并回车；TUI 还需保存。保存时间必须与实测状态对应。
3. 按原有刷图流程运行并比较游戏实值与日志范围。只有原本已有的完整可靠舰队扫描才会学习，不需要为了本功能增加调度任务。满心情时可能无法得到新的相位信息。
4. 若已使用舰队扫描且满足现截条件，可比较扫描前后 `RecoveryState.segments` 与之后的心情范围。重启后应继续沿用学到的区间；共享任务需确认同一实际舰队。
5. 更换舰船或恢复条件后重新校准；记录实值、日志及出现偏差的时刻，核对速度和差值。未在真实账号运行本次验收。

保证前提仍是准确初值与时间、固定且一致的恢复条件、无漏记出击、全 S 胜；学习还要求采纳的读数准确。温泉、饮料、混合恢复速度以及真实结算／识别时点偏差不在这次 3 点模型保证内。
