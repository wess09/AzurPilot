# 资源管理

> 将任务获取、用途与库存核对记录到本地账本，在资源统计中支持精细化管理。

## 1. 模块概述

实例的「资源统计 → 资源管理」打开 `/i/:instance/statistics?view=management`，标签位于「资源趋势」旁边；旧 `/i/:instance/resources` 链接自动跳转。页面将来源任务、资源与用途任务连成桑基图，支持资源与任务筛选、最近 24 小时 / 7 天 / 30 天及自定义区间、库存搜索、分页明细和完整 CSV 导出。石油控制设置也放在本页，通过已有 `config.get` / `config.patch` 保存。
资源管理不参与统计卡片的隐藏、组合或排序，即使资源趋势被隐藏仍保留入口。刷新保留资源管理标签，切换回统计分类恢复该分类原有控件与数据读取。

## 2. 模块职责

### 负责

采集已有任务的奖励和已确认交易、对账、按实例查询来源与用途，并提供筛选、导出和石油控制设置。

### 不负责

不为统计唤醒或操作游戏，不推测未识别的数量，也不从历史库存重建不存在的交易。

## 3. 模块位置

| 位置 | 职责 |
| --- | --- |
| `module/statistics/resource_flow.py` | 运行范围、收支与库存 SQLite 账本、聚合 |
| `module/statistics/resource_tracking.py` | 奖励去重、购买与科研消耗、战役末轮核对 |
| `module/api/resource_service.py` | 只读查询、区间校验、库存回退 |
| `frontend/src/pages/Statistics.tsx` / `ResourceManagement.tsx` | 标签入口、筛选、CSV 与控制设置 |
| `frontend/src/resources/` | 桑基图守恒、绘制、样式及单元测试 |

## 4. 核心入口

`alas.py::run()` 为每次任务调用建立实例、任务与运行身份。普通调度、自定义调度及手动任务都可记账；石油自动控制仅原调度生效。`Device.screenshot()` 和 `Control.click()` 旁路读取任务已有奖励画面，不为统计新增截图任务、点击或导航。奖励模板复用普通掉落、委托、科研与大世界目录，已知物品的正整数数量写入收支账本。同组每种奖励布局只记录一次，复读、重点击或返回上一布局不重复；连续两帧离开奖励画面或正向检测到委托经验结算后，重新接收下一组奖励。信息栏遮挡时暂不解析。

`resource_flow.record()` 用于已确认交易，`observe()` 用于可靠库存，`report()` 用于本地区间查询。扩展游戏采集时优先复用这些入口。

## 5. 核心组件

记录依据有四种：

| 依据 | 来源及语义 |
| --- | --- |
| 已确认交易 | 普通、凭证、大世界商店确认购买后记录明确单价与实际购买数量；扣除同次购买已识别的物品奖励，避免商品重复入账。科研启动成功后按项目目录记录物资、魔方与心智单元消耗。建造数量经准备阶段核对、订单提交成功后记录实际支付的物资、魔方或建造券。后宅按已确认的石油价格与数量记录购粮；自动清油还要确认石油实际下降。购粮期间自然恢复等差额由库存复核另行记录，不抵消实际购买价格。 |
| 奖励识别 | 当前任务的已知奖励模板与数量。恢复、启动或清油观察遇到遗留奖励时将任务标为「待归因」，不归给恢复操作。 |
| 任务内净变化 | `LogRes` 的可靠资源读数，减去上一读数之后已记入的明确交易，只记录剩余差额。战役结束或安全切换回选图页后，以两帧一致的石油、物资和可见活动 PT 核对末轮收支，次数停止仍归给实际刷图任务。游戏卡住等异常直接进入原恢复路径，不追加核对。 |
| 待归因变化 | 跨任务或离线读数差额、活动 PT 重置等库存校正；活动商店同次运行内的 PT 减少作为正常支出。首次有效读数只建立基线，不把历史库存当成收入。 |

## 6. 工作流程

任务建立归因范围 → 从已有画面识别奖励或业务确认交易 → 原子记账 → 可靠库存减去已记交易进行复核 → API 聚合完整筛选区间 → 页面显示流向与证据。同一弹窗重复识别只入账一次；任务退出后归因范围必定释放。

## 7. 调用关系

上游是任务运行器、设备已有帧、商店购买、科研启动、后宅与 `LogRes`。下游复用现有物品模板、仓库目录及共享普通总库连接；WebUI 通过现有 WebSocket、配置事务和 ECharts 消费数据。

## 8. 数据流

常用货币包括石油、物资、钻石、心智魔方、活动 PT / UR 点数、核心数据、勋章、功勋、舰队币、行动力与大世界凭证；物品覆盖仓库目录及奖励中实际识别到的已知模板。完整仓库扫描成功后同步材料库存。没有观测到的库存显示 `—`，不填成零。

## 9. 状态模型

任务归因范围包含实例、任务、唯一运行 ID、奖励识别器及本轮已识别商品数量；异常也会退出范围，下一任务不继承。库存保存上次有效值与交易游标；只有本次运行的前后观测才将残余变化归给当前任务。

## 10. 配置

`General.OilControl.Enable` 默认关闭，`General.OilControl.Target` 默认 24000，可设为 1000 至 24999 的整数。页面使用现有配置事务保存，原调度之外显示配置但不触发自动清油；统计采集本身无需开启额外任务。

## 11. 异常与错误处理

解析或账本写入故障记录 `[资源管理]` 原因并保留原业务流程。可靠读数缺失时不写零。日期或筛选参数非法时 API 返回 `INVALID_PARAMS`，页面可修改并重新查询；游戏卡住等异常继续沿用原恢复机制。

## 12. 并发与线程模型

任务身份使用 `ContextVar` 隔离，游戏线程同步旁路读取当前帧，模板按进程延迟缓存。SQLite 对账在 `BEGIN IMMEDIATE` 内完成，连接按事务释放。页面合并连续统计刷新事件、忽略旧查询迟到响应，并在卸载时销毁图表和尺寸观察器。

## 13. 缓存与持久化

实际配置目录 `azurpilot.db` 使用原生 `resource_flows` 与 `resource_balances` 表，按实例隔离，不上传资源账本。交易内各资源原子写入，并支持事件键幂等；数据库写入失败只记录原因，不中断游戏任务。最近库存可回退到有效仪表盘读数及仓库快照，默认模板时间不视为观测。

## 14. 生命周期

账本表按首次读取或写入建立；关闭任务只释放运行身份，不删除历史。打开页面查询本地记录，切换实例重新获取该实例数据；页面卸载终止更新、清理事件订阅与图表。模型和模板缓存随游戏进程退出释放。

## 15. 扩展方式

新增资源优先使用已有目录标识；未知数字模板不当作资源。添加已确认交易入口时传入有符号整数变化，在正向确认成功后调用 `record()`；若同次奖励已入账，扣除本轮识别数量以避免双计。新增余额入口只提交可靠数值，不用识别失败的默认零。

## 16. 修改注意事项

每种资源独立缩放，来源任务在左、资源在中、用途任务在右。节点与提示显示实际数量，不把不同资源的流线宽度当成价值比较。收入不足以覆盖支出时补「库存支出」，剩余收入补「区间结余」，两侧保持数量守恒。「待归因」使用灰色节点，库存表的获取和消耗不包含库存校正，校正额单列。

汇总覆盖完整筛选区间，不受当前明细页影响。导出按每批 1000 条读取全部筛选记录，固定起止时间及记录 ID 上界，运行期间新增数据不会导致分页重复或遗漏。日期使用本地时间，起止递增，查询区间最多 366 天。切换实例或筛选时忽略旧请求的迟到响应。

## 17. 已知限制

账本只包含功能启用后的实际记录。未经过支持画面的手动操作、未知模板、未观测的用量不能追溯到具体任务；同一任务内的库存净变化可能包含自然恢复，也不能冒充每笔战斗的纯消耗。图表及明细保留记录依据，便于之后补充更精确的交易入口。

## 18. 示例

只读 WebSocket 方法 `statistics.resourceFlows` 接受 `instance`、`days`、可选 `start` / `end`、`resource` / `task`、`offset` / `limit` 和导出用 `through_id`，返回库存、区间聚合、任务流向、分页明细及石油控制设置。查询与页面刷新仅访问本地数据，不启动游戏。前端契约由 API 生成器维护。

选择「石油」和「委托」可查看委托收入；点击右侧主线节点可筛选主线支出。切换所有资源后各资源独立缩放。超过控制线时先运行已启用、已到期且无故障冷却的主线或活动图，图因心情等原因冷却时转后宅购粮；清油优先于委托，停止和恢复优先于清油。结束后还原任务顺序与临时参数，不强制重置 `NextRun`，不新增定时唤醒。

## 19. 调试方法

`tests/test_resource_flow.py` 使用临时配置和 SQLite，覆盖交易幂等、库存对账、实例隔离、末轮耗油归因、PT 支出和重置、购买奖励去重、已有大世界奖励截图及真实 WebSocket 查询和配置保存。`tests/test_oil_control.py` 覆盖原调度优先级、委托溢出恢复、心情冷却转后宅、临时参数还原和重试边界。前端 `src/resources/graph.test.ts` 核对守恒与缩放；`e2e/resources/mock.spec.ts` 使用模拟服务验证图表、筛选、分页、全量 CSV、设置持久化和窄屏交互。以上流程不连接真实账号。
