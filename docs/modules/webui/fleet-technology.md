# 舰队科技列表

扫描中的图像省略号必须紧邻名称正文；短名右侧空白中的卡面亮点不能把普通舰误判为截断的特殊版本。

## 页面与资料

入口是「舰队管理 → 舰队科技」，路由 `/i/:instance/task/FleetTechnology`，与舰队信息、心智计算器并列。页面布局与蓝色表头参考[碧蓝航线 Wiki](https://wiki.biligame.com/blhx/舰队科技)，支持组合筛选、搜索、排序、每页 50 条、固定表头和窄屏横向滚动。阵营/分组额外提供基于资料的 μ 兵装、小型舰筛选，不改变舰船实际阵营。

有有效扫描快照时默认显示「本轮扫描」，只从 `last_scan.ships` 重建本次确认的群组与实读等级，待核对项单列；本次清单缩小或为空时不回退混入旧记录。「累计记录」显示完整目录和历史科技、人工校正。顶部统计明确属于累计科技，编辑模式切换到累计记录；编辑不改写本轮原始读数。没有可用快照的旧实例继续显示累计记录。保存时间用于区分上次已保存结果与尚未提交的新扫描。

匿名浏览器对比：[累计记录](images/fleet-technology-scan-history.png)、[本轮扫描](images/fleet-technology-scan-latest.png)。两种视图使用同一批历史数据，本轮实读等级独立显示。

静态资料离线打包。`assets/ship/fleet_tech.json` 按 Lua `ship_data_group.group_type` 保存可见图鉴、编号、方案分类、三阶段科技点、获得与 120 级加成及四大阵营升级加成；名称、稀有度和类型关联现有 `ship_data.json`。来源提交和日期来自本地 Lua Git 快照，不代表已实时同步游戏服务器。全部、有科技、无科技均可显示；无科技的数值列显示破折号。

## 个人记录与状态

隐藏状态 `FleetTechScan.FleetTech.Record` 随实例配置保存和备份：

- `observed`：以群组 ID 为键保存扫描到的最高历史等级，只增不减。
- `current`：该群组当前已确认的最高等级；局部扫描不能以低级副本降低既有记录。
- `absent`：完整有效全船坞扫描确认未发现的群组，保留历史等级。
- `manual`：每个群组的获得、满星、Lv.120 和最高等级人工覆盖；未指定字段继续使用自动证据。
- `manual.<群组>.level_toggle`：单击完成的低/高等级端点，刷新、重进或重启后仍可恢复原等级。
- `nations`：四大阵营手工录入的科技等级，空值为未知，0 为确认未升级。
- `last_scan`：等级范围、到底状态、数量核验、群组/等级清单和稳定摘要。
- `review_ships`：未确认的卡片与候选群组，不作为获得证据写入。

没有有效获得证据的舰船默认未获得，不再设“待记录”筛选。着色与 Wiki 一致：未获得不标色，已获得但未到 120 级只标绿“解锁”格，达到 120 级后整行标绿，125 同样达标。默认表格不增加状态标签列，等级可通过行提示或编辑模式查看。零科技舰船也有完整的获得和等级记录，只有点数/加成为空。已获得舰船的当前有效等级严格大于 100 时默认满星，100 级及以下仍未确认；人工明确设置的满星或未满星优先。本轮快照按本轮实读等级使用相同边界，不借用历史高等级。默认判断只在读取时计算，不改写扫描或人工记录；满星点数计入“已确认科技点”，仍未知的满星不计点数。

编辑模式单击解锁切换获得状态，单击完成切换等级；满星点数单元格也可单击记录。105 级在 105/120 间切换；原 120 级在 100/120 间切换；原 125 级保留 125 这一恢复端点。未获得舰船点击完成会同时确认获得并录入 120，避免矛盾。快捷操作以群组和绝对目标提交，重试不会额外反向切换。正常浏览模式不修改记录；仍可补录等级和恢复自动记录。

失败保留浏览器草稿和提示，自动刷新不能推进待提交草稿的版本；冲突时主动重载最新记录后再提交。人工覆盖优先于扫描。总属性累积已确认获得/120 加成及已录入阵营等级；阵营表的 add 已是该等级累计值，只加入选中等级一次，导驱/风帆子类不重复累计。

## 扫描与兼容

独立工具 `FleetTechScan` 使用 `FleetTechScan.FleetTech.MinLevel/MaxLevel`，默认 95–125（含边界），满足 `1 ≤ 最低 ≤ 最高 ≤ 125`。心智任务范围和计费规则不变，两个任务不会覆盖彼此清单。兼容导入已有心智清单须在科技页面主动执行。

“扫描船坞”先通过 `config.patch` 保存所选范围，再通过 `tasks.run(FleetTechScan)` 启动独立工具。任务须同时具备配置定义、`alas.py` 入口和 `module/submodule/utils.py::get_available_func()` 注册；API 启动校验与工作进程分发共用该清单。实例运行时不能再启动扫描。回归入口 `tests.test_api.SocketApiTests` 使用真实 WebSocket 路由和任务清单，仅替换工作进程以避免操作设备。

科技扫描复用页面稳定、三排行进及滚动配准，使用自己的可见图鉴群组目录与合并方式，不套用心智按名称合并或计费排除。名字、等级可靠后按群组保存，重复副本取本轮最高等级；局部扫描只读到低级副本时保留既有最高等级，本轮原始清单仍单独保存。改造用实际改造名关联原群组，II、META、小型和兵装保持独立。飞机、战列字形提供正向舰种证据，使同名加贺、天城分别保存；同名同舰种不能凭稀有度、排序或全收藏假设选人，候选在页面供手工确认。

共享扫描器对一个阈值边界行内的抗锯齿像素进行二维八邻接核验，前后行仍采用严格颜色，首尾端点不扩张，不修改通用 `Scroll` 阈值。圆角采样不依赖固定横向跨度。暂时无法识别滑块只使该帧失去底部证明；卡片有独立唯一位移证据时可以继续范围扫描，不能据遮挡或静止误报到底。

严格滑块仅差轨道终点两行时，另行核对逐行收窄、八邻接且延伸至终点的圆角端帽颜色；
该正向证据仅用于底部退出，不修改滑块端点和位移标定。末页不必对齐三排目标，只读取完整可见行。
主动导入心智清单支持带舰种/阵营限定的同名身份，按确认的群组分别累计；未限定的约克、新月等歧义名称继续跳过。

同名同等级的重复卡片可能在相差整行的多个位移上同分，整行移动甚至看起来没有变化。滑块两个端点同向移动、已核实的按住结束手势边界及此前明确位移的比例校准可进一步约束候选；仍须得到唯一图像匹配，不直接采用触控距离。无独立证据的重复画面不能当作零位移，当前步最多三次新帧复核，无法确认时保留旧结果退出。
小距离按住拖动的物理幅度小于半排行距时，可以使用包含零和反向候选的对称界限核验；滑块亚像素移动不可见也不直接中断，仍须图像在界限内唯一匹配。
该手势范围仅用于重复纹理消歧；唯一重叠图像不以触控长度作为硬上限。滑块双端至少两像素同向移动时的独立约束仍是硬检查，不因手势提示而覆盖。

卡片缺格在当前页最多重读三次；有可靠行位及同排其他卡片证据时，只把缺失卡位保留为未知等级待核对，其余舰船继续处理。整个页面无法确认时不凭网格捏造舰船。等级、编队或排序疑点仅作用于原卡位及必要交界；之后完整可靠的普通舰页面可恢复早停，历史单点疑问不强制扫到底。待核对项仍保留，当前页存在疑点、缺格或未越过等级下限时不能早停。

改造别名同时读取 Lua 的 `sharecfg` 与 `sharecfgdata` 皮肤表，以真实群组关联；不连续的改造编号也不能被误当作剧情条目丢弃。改造后舰种采用同组实际改造类型（例如战列改航战）核对。小型分组采用资料标记及同阵营同舰种的“小＋原舰名”关系，普通舰名中的“小”不作为排除条件。`MET…`、μ 标记与唯一名称的截断后缀保留身份含义；II 家族要求多次明确后缀。失败字图只做有界笔画复读，两种处理独立确认相同群组后采用，不添加特定舰名替换表。

扫描前经主界面重新进入船坞，清空隐藏搜索词，再确认搜索关闭、重置收藏与筛选并确认顶部；仅收起搜索框不能证明关键词已清空。非底部页必须完整三排七列。核实新页并新增物理船位后重新计量滚动期限，有界 OCR 复读不占用下一段滚动期限；重复旧船位不能续期。仅 **1–125、无过滤、到达底部、物理卡片数与船坞数量一致且无未确认条目** 时更新缺失状态。局部范围、OCR 疑点、页面缺格、取消、异常和未到底不会清空已有记录；扫描中途不提交，成功后在事务内合并最新人工校正。新舰船无证据时默认未获得，既有历史和人工记录不因资料生成而删除。
船坞数量共用 `ScanDockAmount` 的原生数字区与严格完整计数器校验，不将越界分子裁成容量。数字未确认时本轮不能据缺失清空已有记录。

原 `MindCalculatorScan.MindCalculator.FleetTechRecord` 只读兼容：新路径为空时读取旧数据，首次编辑或扫描复制完整记录到新路径，旧路径保留作迁移备份。读取不会触发写入，合法心智扫描范围也不迁移覆盖。

自动扫描当前支持国服，其他游戏服仍可手工记录。`cache/fleet-tech-scan-diagnostics` 标志保留全部页原帧和卡位诊断，用于离线复核；不减弱排序、位移或页完整性校验。

## API

心智清单导入优先读取已确认的 `group_type` 并重新核验名称与群组一致性；
旧无身份字段仅接受唯一名字别名，歧义与伪造身份不能写入获得证据。
科技与心智扫描均可对重名卡片追加阵营筛选复核：正向核实筛选按钮、重扫完整范围，
只有原始物理卡位与复核结果的舰名、等级多重集一致且全部确认时才替换歧义条目。
范围、物理总数和完整扫描证明仍来自首次全船坞扫描；取消或任何复核异常均不提交。
真实末页继续使用严格滑块及连通收窄到轨道末端的圆角端帽证明，不扩大运动标定或通用滚动阈值。

| 方法 | 行为 |
| --- | --- |
| `fleetTech.catalog(instance)` | 只读离线目录与来源版本 |
| `fleetTech.report(instance)` | 只读实例状态、范围、点数与加成 |
| `fleetTech.patch(instance, revision, changes, nations)` | 事务编辑人工覆盖/阵营等级；快捷变更使用 `toggle` 与绝对 `target`，版本冲突拒绝写入 |
| `fleetTech.syncMind(instance)` | 幂等累积该实例已保存的确认清单 |

两个写接口标记 `mutates=True`，沿用认证与演示模式写保护。状态字段仍禁止通过普通 `config.patch` 整体替换。

## 生成与更新

使用同一 Lua 快照分别运行：

```powershell
uv run python -m dev_tools.ship_data_extractor --lua-repo <Lua仓库路径>
uv run python -m dev_tools.ship_data_extractor --lua-repo <Lua仓库路径> --names-only
uv run python -m dev_tools.ship_data_extractor --lua-repo <Lua仓库路径> --fleet-tech-only
```

校验图鉴与科技的群组关联、编号唯一性、非空名称、完整字段及点数汇总。目录在进程内缓存，部署资料后由应用更新重启加载。更新 fork 的上游方式与本机路径只记在被 Git 忽略的本地技能，本文不复制本机路径。
