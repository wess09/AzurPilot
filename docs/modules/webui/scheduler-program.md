# 卡片式自定义调度

隔离运行与接口验收结果见[验收记录](scheduler-program-verification.md)。

每个实例的入口位于「任务配置 → 系统 → 自定义调度」。通用设置中的「自定义任务优先级」旁也提供入口。默认仍使用原调度；打开编辑器、模拟或保存草稿不会启用方案，必须点击「应用方案」。

## 编辑与操作

从左侧卡片库点击或拖入卡片。卡片的执行入口在左侧，出口在右侧；方形端口控制执行顺序，圆形端口传递数据。卡片标题按功能分类着色，端口颜色按兼容的数据类型分组：数值与时长同色，资源记录与对象同色，列表与任务列表同色。布尔值、时间、文本、任务和任务结果分别使用独立颜色。不兼容的数据端口及执行与数据端口之间不能连接。

「任意值」端口用彩环表示，可以接受不同类型；连接后显示对端的类型颜色。拖动连线时，通用输入也显示当前来源的颜色。连线颜色跟随来源端口。

常用参数可以直接在卡片内编辑，包括资源种类、当前值/上限/总量、有效期、自动刷新、指定任务、运算符、常量、等待时间和变量。行动力的当前值与含体力箱的总量分别显示。已接入数据线的字段显示「由连线提供」，手填值不会覆盖连线。右侧属性面板用于任务临时参数、任务列表、优先级、组合端口等详细设置。

| 操作 | 方式 |
| --- | --- |
| 框选 | 在画布空白处按住左键拖动 |
| 多选 | Shift、Ctrl 或 Cmd 配合点击 |
| 平移 | 中键、右键拖动，或按住空格再拖动 |
| 复制、剪切、粘贴 | Ctrl/Cmd+C、X、V；也有工具栏按钮 |
| 撤销、重做 | Ctrl/Cmd+Z、Shift+Z；Ctrl/Cmd+Y 也可重做 |
| 删除节点或连线 | Backspace 或 Delete；程序入口受保护 |
| 全选、取消选择 | Ctrl/Cmd+A、Esc |
| 删除连线 | 双击连线，或选中后删除 |

输入框、下拉框和文本编辑区域保留浏览器自己的文本操作，不会触发节点删除。拖拽中由 React Flow 管理位置，松开后提交一次文档变化。框选的一组节点可以整体移动。使用「从左到右排列」重新布局，使用「展开画布」隐藏两侧面板；缩放不改变程序逻辑。

## 模式与运行

- 原调度保留已有行为。
- 原调度额外支持通用设置中的石油自动控制：默认 24000，超线后临时优先清油，先运行到期的图，冷却时后宅购粮；清理后恢复原业务顺序。此自动流程不用于增强调度或完全接管。
- 增强调度只向程序提供原调度中已启用且已到期的候选任务，程序选择任务并设置本次参数。
- 完全接管由程序决定业务任务，包括原配置中未启用的任务；内部业务派发进入请求列表，系统恢复仍使用现有恢复通道。

任务、等待和资源刷新会让出解释器，完成后继续对应出口。继续条件是无副作用的组合子图，在现有任务切换检查点检查；需要停止时使用任务已有退出流程。缺少检查点的任务完成后才响应。

应用方案前由后端校验。运行中的应用在任务安全边界生效，等待时每隔至多五秒检查变更。程序错误停止业务派发并显示原因，不自动切回原调度。主程序结束后保持等待；持续调度需使用循环卡片。重启从入口开始，普通变量重置，显式持久变量、配额和冷却记录保留。

资源成功观察时间与 Dashboard 的变动记录分开保存；同值识别可以更新新鲜度，缓存回退和失败读数不更新。默认有效期五分钟，可在卡片中修改。主动刷新支持石油、物资、行动力、黄币和紫币；其他资源使用任务观察记录。同组刷新合并，并至少间隔六十秒；刷新仅在任务边界执行，不购买、兑换或使用补给。

## 保存、模拟与接口

`module/scheduler/` 包含公共模型、卡片注册、图校验、解释器、模板、资源观察与调度适配。编辑器位于 `frontend/src/pages/SchedulerProgram.tsx`，画布和编辑辅助模块位于 `frontend/src/scheduler/`。

普通调度定义与状态使用实际配置目录 `azurpilot.db` 的十七张原生表。草稿与已应用文档、图、节点、连线和端口按内部序号保序；参数及变量使用具有明确归属的类型化值树。用户 ID 和连线端点保留草稿语义，不新增唯一约束或节点外键。写入使用 `BEGIN IMMEDIATE` 和 revision 冲突检查。复制及配置导出只带方案；删除先归档配置、单实例调度切片和安全历史，统计保留。恢复重新映射内部引用，只导入对应实例并拒绝覆盖已有状态。认证历史继续使用 `config/scheduler/<实例名>.sqlite3` 的专用安全存储。图文件分享仍使用 JSON，完整约定见 [普通业务数据存储](../infra/persistence.md)。

`scheduler.program.catalog/get/save/validate/simulate/apply/state` 均通过 `/api/v1/ws` 调用，参数与公共模型由 API 导出工具生成。worker 通过带 `run_id` 的专用有界队列发送轨迹，查询状态不初始化设备或新 worker。

模拟器调用后端同一解释器，输入模拟时间、资源、任务状态和结果序列；单步与连续运行均不连接设备、不写真实配置或持久变量。前端 mock 也通过隔离 Python 进程调用该解释器。开发验证使用临时配置、模拟设备和浏览器 mock；真实账号验收需另行指定实例与任务范围。
