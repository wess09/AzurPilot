# 作战委托：规则、问题与验证

验证日期：2026-11-16 至 2026-11-17。实机为国服 1280×720，使用 ADB。

依据包括游戏内说明、实际操作，以及 [#1503：关于作战委托优化一事](https://github.com/wess09/AzurPilot/issues/1503)。游戏规则可对照[2026 年 8 月 27 日改建公告](https://www.taptap.cn/moment/841357693040984838)。

## 功能与收益

- 基础委托只提供大讲堂熟练度，不消耗石油或委托书；不能按普通刷图理解其掉落。
- 投入作战全权委托书后，为对应次数追加关卡掉落，并消耗额外石油。委托书也可兑换可用时间，这两种用途需要分别考虑。
- 关卡需有一次完整、全程自律且未中断的连续作战记录；单纯通关、三星或达到 100% 不代表委托已开放。
- 每天有 8 小时可用时间，服务器 0 点重置。仍有额度时，最后一次可超出剩余额度；额度为 0 与 OCR 识别失败必须区分。
- 委托进行时，主线、活动和作战档案均受出击限制。完成后的掉落委托还需要领取奖励，才能完成交接。

## 本次发现与修改

| 问题 | 原因与影响 | 当前处理 |
| --- | --- | --- |
| 配置填 1 次仍不断启动 | 原选项表示每批关卡数，任务完成后会再开一批 | 改名为“每批委托次数”；新增普通委托每日启动批次，默认 1，0 表示不限 |
| 出击等待委托结束后再次被阻塞 | 委托任务先到期，领奖后立刻新开，出击尚未到其推迟时间 | 临近出击时推迟新委托；按下一次出击时间限制批次数，为界面切换预留时间 |
| 额度不足时反复加次数 | 请求次数超过当前游戏上限，目标不可达 | 按游戏实际最大值限制次数；上限为 0 不输入；识别失败有明确超时出口 |
| 自动补时间不能按请求次数工作 | 游戏最大次数已先按剩余额度限制，之后才检查时间 | 先按请求次数检查额度、油量与留书条件，再兑换时间和设置次数 |
| 配了掉落委托，没书却启动熟练度委托 | “投入量拉满成功”与“实际投入大于 0”混为一谈 | 开启使用委托书时，投入量为 0 则推迟 |
| 免费模式被油量门槛挡住 | 两种收益模式共用石油检查 | 免费模式不按额外油耗门槛推迟；补解锁记录所需的真实出击仍检查石油 |
| 油耗 317 识别成 1317 | 原区域包含油桶图标，图标被识别为前导数字 | 调整资源区域，提取绿色/红色数字并去掉图标及中文单位 |
| 冲突处理保存结束时间时报错 | `cross_set` 收到列表路径，实际实现要求可作为字典键的路径 | 使用字符串路径，并直接把刚识别的结束时间传给推迟逻辑，兼容批量保存 |
| 领奖中途退出 | 新船与总奖励出现前会短暂露出选关页 | 必须处理过总奖励确认，再检查选关页稳定出现 |
| 连续作战结束后被数字识别挡住 | 结算的计划次数 OCR 失败，即使作战已完成也无法离开 | 完全删除结算次数的 OCR、校验和等待分支；识别结算画面后离开，正常批次按启动次数记账，已检测的中断不计为整批 |
| 作战档案无法配置 | 委托的活动候选仅含当前活动 | 加入各地区档案候选，复用档案地图导航；补解锁时启用现有密钥确认处理 |

普通委托的每日批次数只在正向确认启动成功后增加，服务器次日 0 点重新计算；达到上限仍会回收现有委托。每周消耗与维护计划独立于普通委托批次上限。

这里采用保留现有委托、为出击预留窗口的交接方式。#1503 提出的自动终止方案未作为默认行为；本次没有引入自动中止已投入委托书的作战。

## 实机验证记录

| 场景 | 实际结果 |
| --- | --- |
| 5-3 补解锁 | 灰色入口 → 完整连续作战 → 重新进入后入口可用 |
| 免费委托 | 5-3 启动 3 次，未花委托书与石油；结束后没有掉落领奖流程 |
| 新账号 12-4 解锁 | 原关卡已三星但入口灰色；完成一次原生连续作战后开放委托 |
| 12-4 掉落委托 | 投入 1 本、委托 1 次；面板需要时间 4 分 46 秒，实际额外耗油 317，详情从 0/1 变为 1/1 |
| 跨主线关卡 | 委托期间进入 12-1，出现阻止提示；“查看委托”进入原 12-4 的真实详情 |
| 付费委托领奖 | 已走过熟练度溢出确认、新船入手、总奖励确认；获得物资与舰船，回到正常选关页 |
| 作战档案自动解锁 | 点击「红染的参访者」A1 灰色入口后，游戏提示需完成未中断且全程自律的连续作战；已自动完成一次，重新进入后入口变蓝，并成功打开、关闭委托面板 |

档案自动解锁流程采用单进程、单线程 OCR、每秒一帧。已验证到委托面板可用，没有发起档案离线委托，因此不把档案委托启动、档案领奖列为实测通过。活动进入、档案地区候选与难度切换有配置及真实地图加载回归；本轮没有宣称所有活动、所有地区都做过实机验证。

## 验证范围

- `tests/test_handover_planning.py`：使用真实内存配置检查出击交接、结束时间写入、每日批次上限、成功启动计数、时间准备与资源边界，以及领奖转场。油耗图像检查只做预处理，不加载 OCR 推理模型。
- `tests/test_handover_stage_navigation.py`：真实地图加载、活动别名、普通/困难切换及档案导航。
- `tests/test_campaign_config_options.py`：档案候选按地区提供，API 保存与运行时重载保留所选档案。
- 原有 `tests/test_sortie_flow.py` 与 `tests/test_handover_reward_popup.py` 覆盖连续作战中断、批次记账和委托弹窗优先级；结算次数识别用例已随对应逻辑删除。

为控制用户设备负载，后续验证按新增行为和失败点定向执行，不重复全量测试、并行 OCR 回放或性能测试。测试配置留在内存或临时目录；实机截图和账号数据没有加入仓库。
