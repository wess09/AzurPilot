## 0. 快速开始（给执行者的话）

**你要做的是**：改 React 组件的 DOM 结构与 CSS 网格，让新版前端的**布局**贴近旧版，而不只是换肤。

**关键结论（已调研完毕，不必重复验证）**：

1. **旧版与新版是两套完全不同的布局模型**，不是"样式微调"能跨越的：
   - 旧版外壳 = **顶栏在上 + 下面一行 flex（图标栏 + 12rem 文字菜单 + 内容区）**
   - 新版外壳 = **CSS Grid 三列（侧栏 + 主内容 + 右栏）**，顶栏在主内容列内
2. **旧版总览页是两列网格**：左列 `minmax(16rem,20rem)` 放「调度器 / 统计界面 / 运行中 / 队列中 / 等待中」，右列 `minmax(24rem,1fr)` 放「日志 + 仪表盘」。新版把调度器与任务队列搬进了右侧栏 `RightRail`。
3. **旧版全部布局规格仍完整保存在 git 历史里**（`master:assets/gui/css/` + `master:module/webui/`），可精确取用，见 §2。
4. **本次只改 `frontend/`，不动任何 Python 代码。** 布局是纯前端的事。
5. 旧版前端**可以跑起来对照**：用户本机有一个旧版实例在 `127.0.0.1:22269`（截图见对话）。若不可用，也可以从 `master` 检出旧版起服务。

**最重要的一条警告**：**不要试图用 CSS 把新版的 DOM "挪"成旧版的样子。** 新版把「调度器」放在 `RightRail` 里，那是 `main-shell` 之外的兄弟节点，CSS 无法把它渲染进主内容区。**必须改组件结构**（把区块从 RightRail 提到 Overview 里），而不是堆 CSS。这次工作的性质是**功能改造**，不是换肤。

**第二条警告**：改结构会牵动移动端断点、无障碍（skip-link / 焦点顺序 / aria）与既有的 5 个主题。**每改一个区块都要回归 light / dark / minimal / legacy-light / legacy-dark 五个主题 + 移动端。**

### 2.4 日志与仪表盘的关系（容易搞错）

旧版**没有独立的仪表盘列**。「资源卡 + 体力变化图表」是 `logs` 列里的 `dashboard` scope，通过日志 bar 上的按钮在 **日志 ⇄ 仪表盘** 之间切换（`app_overview.py:203` 的 `dashboard_btn`）。见截图：点"日志"按钮才切回日志。

新版把资源卡常驻在主内容区顶部、日志在监控面板里 —— 这是**两处结构差异**：资源卡的位置，以及"日志/仪表盘"的切换方式。

### 2.5 移动端

出处 `alas-mobile.css`（3730 B）。旧版在窄屏下把 `aside` + `menu` 收起为抽屉。新版已有等价的 `.mobile-open` / `.rail-open` 机制（`layout.css:130`），**建议沿用新版机制，不要照搬旧版**。

### 4.1 外壳：顶栏跨全宽，侧栏回到旧版位置（**只有实例视图要改，不要图标栏**）

> **前提**：本节只在**实例视图**（`instance` 存在时）生效。主页视图（`#/`）的外壳**必须保持新版现状**。`App.tsx` 里靠 `instance` 是否为空来分支。

**改 `App.tsx:95-110`**：

1. 把 `.app-shell` 从 `grid-template-columns: [sidebar] [main-shell]`（+右栏）改成**两行**：第一行顶栏（跨全宽），第二行文字菜单 + 内容。

**改 `frontend/src/styles/layout.css`**：把 `.app-shell` 的 grid 定义换成对应结构。

**建议用 grid 而不是 flex**（旧版用 flex 是因为 PyWebIO 的 scope 不能嵌套 grid，新版没这个限制）：两行 grid + 第二行三列 grid，比 flex 更好控制。

**要小心的**：`.app-shell.with-rail` 的存在性（见 §4.4）；`.topbar` 现在依赖 `isolation: isolate` + `.glass-material` 做毛玻璃折射（`apple.css:83-85, 145-150`），搬家后要确认玻璃层仍然包住顶栏。

## 5. 必须处理的坑

### 5.1 结构改动会让 `.skip-link` 掉进网格流

`.skip-link` 的 `position: fixed` **不在任何共享文件里** —— 它分别写在 `apple.css:264` 与 `minimal.css:122`，也就是说**每个主题入口都得自带一份**。`legacy.css` 已经补了；如果重构外壳时把它漏掉，它会变成 `.app-shell` 的第一个 grid item，**占掉第一列**，整个布局错位。

**改外壳结构时务必确认 `.skip-link {position: fixed}` 在改动后的主题入口里仍然存在。** 相关：这是上一轮实际踩过的坑。

### 5.2 主题入口必须自带结构性规则

共享层（`tokens/layout/components/insights/home/forms/theme-primitives`）**不提供**布局、尺寸、层级、flex/grid 定义。平时由 `apple.css` 承担。`minimal.css` 与 `apple.css` 有 **81 个选择器是各写一遍**的。

**这意味着**：如果你新增了一个主题入口，或者把某个区块的定义从 `apple.css` 挪走，必须同步 `minimal.css` 与 `legacy.css`，否则那两个主题下布局会塌。

**自查手法**：改完跑一次变量/规则覆盖检查 —— 收集所有 `var(--x)` 引用，确认每个都有定义（上一轮用 Python 脚本做过，零未定义）。

### 5.3 `public/theme.css` 排在注入 `<style>` 之后

`frontend/public/theme.css` 是 **classic 主题的实际变量来源**（不是可选的装饰层），作为 `<link>` 被追加在 `<style data-azurpilot-skin>` **之后**，同特异性必赢。写在 bundled CSS 里的 `:root` 调色板会被它整个盖掉。

**改布局时不涉及颜色所以一般无碍**，但如果你在布局改动里顺手调了某个 `:root` 变量，记住要用 `:root[data-theme='...']` 提高特异性才生效。

### 5.4 移动端断点是同一个 CSS 文件里的两条路径

`layout.css:130` 的 `@media (max-width: 950px)` 把 `.app-shell` 从 grid 改成 `display: block`，侧栏/右栏改成 `position: fixed` 的抽屉。**改桌面布局时必须同步改这一条**，否则窄屏会碎。

### 5.5 预览浏览器的无障碍默认值会误导你

用 Browser 面板 / Playwright 无头浏览器看效果时，`prefers-reduced-motion: reduce` 与 `prefers-reduced-transparency: reduce` **默认是 true**，会触发 `tokens.css:42` 与 `theme-primitives.css:175` 的降级规则：

- 所有 transition / animation 被 `!important` 关掉
- 毛玻璃与壁纸被隐藏

**不要把这两个降级误判成 CSS 写错了。** 要验证真实观感，请让用户在自己的浏览器里看。

gh pr create --base dev --head feature/旧版界面布局
